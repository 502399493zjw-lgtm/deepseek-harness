# Agent Note: Codex 账号额度全局优先级

Status: implemented

[English](2026-08-18-codex-global-account-priority.md) | 中文

## 问题

OpenAI Codex 设置页允许用户查看一个账号，但另一个默认 profile 控件只管理之后创建的 Session。这种拆分会让所选账号看似已生效，实际上却没有；只影响新对话的默认值也无法表达所需的账号池策略：在全局范围内优先消耗一个账号的额度，只有相关额度耗尽后才使用其他账号。

模型请求还可能携带上一次请求留下的提供方续传状态。如果更换凭据时不清除该状态，就可能用另一个账号的凭据发送由原账号创建的续传标识。

## 决策

Host 持有的 profile 文档只存储一个有序 profile 列表，不再保存独立的 active profile id。第一个 profile 就是全局额度优先账号。选择账号卡片只切换浏览器详情；确认**优先使用**后，同源 Host 修改接口会把该 profile 移到最前。当前优先账号仍保留同一个轻量操作，因此重复确认具有幂等性。浏览器重新获得完整 ready 状态后才移动**优先**标记。修改或刷新失败时保留原标记，并继续提供该操作以便重试。

每次 Codex 模型请求前，Host 都从头到尾扫描 profile。只有请求模型对应的额度桶或该 profile 的工作区个人限额明确为零时，才跳过该账号。`gpt-5.3-codex-spark` 使用 `codex_spark` 额度桶，其他 Codex 模型使用 `codex`。缺少额度桶或用量无法读取时仍保留高优先级 profile，因为缺失不能证明额度耗尽。如果所有 profile 都被确认耗尽，已有 Session 保留当前 profile，尚未绑定的 Session 使用第一个 profile。

Session 绑定仍只存在于当前进程，但可以在每次请求边界变化。compare-and-replace 操作确保并发请求不能覆盖额度检查后已经变化的绑定。成功提交不同 profile 的请求会在解析凭据前关闭该 Session 的提供方 WebSocket 续传状态，因此下一次提供方调用会在同一个账号下发送完整 Harness 上下文。顺序调整会在新对话和已有对话的下一次请求生效；它不会中断或重放正在进行的请求。

## 考虑过的替代方案

**保留独立的 active profile id。** 两个持久权威可能发生冲突：active id 指向一个首选账号，而有序分配器把另一个账号作为第一候选。一个有序列表即可同时表达界面优先级和分配顺序，无需协调。

**选择账号卡片时直接修改。** 账号卡片还用于查看额度。让一次查看操作改变全局请求凭据会隐藏高影响操作，也很难区分误触与有意变更。

**永久固定已有 Session。** 永久固定会使已确认的全局优先级在已有对话中失效，也无法在用户需要时执行额度回退。请求边界重新分配不会改变进行中的调用，并且会明确重置提供方续传状态。

**把缺失或无法读取的额度视为耗尽。** 用量接口短暂失败就会把付费工作静默路由到低优先级账号。只有明确的零值才足以跳过 profile。

**使用另一个账号重试或重放已开始的提供方请求。** 跨账号重放可能重复产生副作用，而且无法证明第一次提供方尝试没有执行任何工作。因此，分配只发生在请求之前。

## 后果

- 一个已确认顺序会在下一次请求边界应用于所有 Codex 对话，自动回退也遵循同一顺序。
- 每次分配都可能在模型请求前执行有超时上限的额度读取。读取失败时会继续使用高优先级 profile，并可能使请求延迟到读取截止时间。
- 侧边栏使用的官方 Codex-home 账号池仍是独立的只读凭据存储；修改 DSH 模型 profile 的优先级不会重排 `quota.accountHomes`。
- profile 文档格式升级到版本 2，并按仓库的预发布兼容策略拒绝已废弃的 active profile 字段。
- 聚焦存储、分配器、路由、组件、响应运行时和组装 Web 测试固定有序优先级、按模型明确零额度回退、已有 Session 重新分配、续传状态重置、幂等显式确认、可恢复失败和设置页中的轻量操作。
